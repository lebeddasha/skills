# Проверка Excel и дозировок

Валидатор `scripts/validate_workbook.py` работает на Python 3.9+ без сторонних пакетов. Только читает `.xlsx`/`.xlsm`; не исполняет формулы, макросы или внешние связи. Старые `.xls`, `.xlsb`, зашифрованные и нетипичные книги требуют другого инструмента. Общий предел — 200 МБ распакованного содержимого и 10000 частей.

## Запуск

Из папки навыка (пути к файлам заменяет Codex):

```sh
python3 scripts/validate_workbook.py snapshot '/путь/оригинал.xlsx' --report '/путь/baseline.json'
python3 scripts/validate_workbook.py check '/путь/оригинал.xlsx' '/путь/заполнено.xlsx' --manifest '/путь/checks.json' --report '/путь/report.json'
python3 -m unittest discover -s tests -v
```

Первую команду выполняют до редактирования. Перенеси `original_sha256` из baseline в манифест. Хеш нельзя снимать задним числом и называть доказательством сохранения оригинала. Валидатор не перезаписывает даже существующий отчет; для нового запуска выбирай новое имя или вывод в терминал без `--report`.

Коды завершения: 0 — перечисленные механические проверки прошли; 1 — обнаружены ошибки; 2 — неполное покрытие, неверный ввод или невозможность проверки. `mechanical_pass` не означает медицинскую безопасность, истинность наблюдений, корректность формульного расчета или полноту задания.

## Манифест

См. [examples/checks.example.json](../examples/checks.example.json). Это образец под условный лист `Лист`, не готовая карта реального шаблона. Нулевой SHA заменяется снятым до изменений хешем. Ссылки имеют вид `Название листа!B7` без Excel-кавычек; допускаются пробелы в имени листа. Диапазоны в массиве ячеек перечисляй поэлементно, не `B2:B10`.

- `schema_version`: 1.
- `original_sha256`: 64 шестнадцатеричных символа.
- `allowed_cells`: конкретные ячейки для изменения значений. Формулы оригинала и стили защищены даже здесь.
- `required_cells`: обязательные ответы. Пустота, пробелы, прочерки, многоточия, TODO не проходят. Обоснованное «данных недостаточно» допустимо в текстовом ответе.
- `arithmetic`: расчеты по значениям фактических ячеек, а не переписанным вручную числам.
- `transitions`: состояния одной лестницы, полные наборы параметров в каждом состоянии.
- `observations`: статус результата и источник, если результат заявлен как наблюдавшийся.
- `not_applicable`: причины неприменимости раздела; использовать только когда в задании действительно нет такой части. Это не способ скрыть недоступность проверки.
- `package_changes`: только точечные обоснования изменения `docProps/core.xml` или `docProps/app.xml` редактором. Остальные изменения частей книги требуют исправления или отдельного анализа, а не широкого исключения.

Валидатор сравнивает структуру листов, содержимое неразрешенных ячеек, оригинальные формулы и остальные части OOXML. Может строго отклонить безвредную пересериализацию редактором; выясни причину, не игнорируй ее автоматически. Потеря рисунка, VBA, проверок данных или изменения именованных диапазонов не принимаются как «обычные метаданные».

## Арифметика

Числа в проверяемых ячейках — отдельные числовые значения или текст с одним числом; десятичная запятая поддерживается. Составные записи не интерпретируются молча. Для них вместо ссылки можно использовать селектор, привязанный к точному тексту ячейки:

```json
{"cell": "Лист!B1", "expected_text": "3 по 8–10", "number_index": 0}
```

Индекс 0 извлечет 3, индекс 1 — 8, индекс 2 — 10. Если текст в книге отличается, расчет отклоняется. Селектор работает и для `result`, например для границ `192–210 с`. Десятичные запятые поддерживаются; дефис между числами трактуется как разделитель диапазона. Единицы и смысл чисел определяет автор манифеста. Нельзя индексом 0 взять 3 из `3:30` и считать это 3 секундами: формат минут:секунд требует отдельного преобразования/ручной проверки. Отрицательные числа не допускаются.

Диапазон проверяй двумя расчетами, по нижней и верхней границе. Пример `3 по 8–10`, темп 3 секунды, два отдыха по 60 секунд: 192–210 секунд, то есть 3:12–3:30. Для каждого расчета используй один и тот же селектор подходов, нужный индекс повторов и нужную границу результата. Не добавляй скрытые числа в шаблон только ради проверки. Если формат неоднозначен или единицы нельзя надежно согласовать, выполни прозрачный ручной расчет с точной цитатой ячейки и укажи ограничение машинной проверки.

`sum` складывает ячейки. `product` перемножает. Для повторов/тоннажа используй одинаковые единицы и учти стороны: подходы × повторы на сторону × стороны; тоннаж дополнительно × внешняя масса. Не умножай на две стороны, если повторы уже указаны суммарно. Тоннаж не равен физиологической нагрузке и не измеряет сопротивление резинки.

`duration` считает секунды:

```
подходы × стороны × (повторы × секунды_на_повтор)
+ отдых_сек × число_пауз + переходы_сек
```

Для работы по таймеру вместо `reps` и `seconds_per_rep` используй `work_seconds`. `sets`, `sides`, `rest_seconds`, `rest_count`, `transition_seconds` обязательны. Число пауз задается явно: для трех обычных подходов между ними две паузы; при чередовании сторон/кругах оно может быть другим. Отдых после последнего подхода не добавляется неявно. В переходы включи нужные объяснения, смену сторон и инвентаря без двойного учета.

Пример: 3 × 10 × 3 секунды + 2 × 60 секунд = 210 секунд = 3 минуты 30 секунд, без переходов. 3 × 8 × 3 + 2 × 45 = 162 секунды = 2 минуты 42 секунды. Эти варианты одновременно отличаются повторами и отдыхом, их нельзя назвать изменением одной амплитуды.

Для блока 12 минут сумма всех частей с отдыхом и переходами должна дать 720 секунд; сессия 60 минут — 3600 секунд. Не растягивай работу искусственно ради заголовка; явный резерв/объяснение может быть отдельной частью. Если значения заданы в минутах, сначала приведи к секундам. Утверждение «15 + 30 + 10 + 10 = 60» неверно: это 65 минут.

Результат, представленный формулой, валидатор сам не вычисляет и как свежий кеш не принимает. Для него нужен пересчет и отдельная проверка в Excel/LibreOffice. Значение RIR не превращается точно в RPE по универсальной формуле; оцени согласованность вручную. Временной диапазон с неизвестным темпом не дает точной длительности.

## Переходы

`states` перечислены в фактическом порядке. Первый `kind: base`, далее `progression`, `regression` либо `repeat`. У всех уровней одинаковые ключи `values`; значения — ссылки на ячейки. Добавь все управляемые параметры, которые могут различаться. У перехода нужны `changed_parameter` и `reason`. Для `repeat` изменений быть не должно. `require_regression: true` проверяет наличие отмеченной регрессии, но ее смысл и направление проверяет человек.

Машина сравнивает соседние значения. Она не понимает, что «легче резинка» может означать меньше помощи, а не меньше сопротивления; это должно быть описано и проверено тренером. Увеличение числа параметров в одном текстовом поле может скрыть двойное изменение, поэтому карта параметров — часть ручной проверки.

## Наблюдения

Статусы: `planned`, `scenario`, `observed`, `unknown`. Для `observed` обязательны `evidence` (файл/таймкод/сообщение пользователя) и `date` (дата наблюдения либо дата сообщения с явным уточнением). Запись о наличии источника не доказывает его истинность — содержание надо сверить. Манифест не является новым медицинским документом.

## Что остается ручным

Соответствие спискам, семантика ответов, полнота всех пунктов, единицы измерения, разумность дозы, клинические выводы, чтение видео, действительно ли меняется только один параметр внутри текста, визуальная верстка и вычисление формул. Проверка сохранности определения выпадающего списка сама по себе не доказывает допустимость нового значения.
